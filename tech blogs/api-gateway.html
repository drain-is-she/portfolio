Purpose of an API Gateway

What is an API gateway?

What is an API gateway?

An API gateway is a single entry point for a client and multiple backend services. First, a client sends an HTTP request to the API gateway. The gateway parses and validates the request. Parsing means breaking the request into structured information.

Before the request reaches the gateway, the network stack handles it across layers of the OSI model:

  1. At the application layer, the HTTP or HTTPS request is constructed.
  2. At the transport layer, TCP segments the data and manages delivery.
  3. At the network layer, IP handles addressing and routing.
  4. At the data link layer, frames are created for local network delivery.
  5. At the physical layer, bits travel over the transmission medium.

At the other end, this process is handled in reverse order so the application can receive the request.

What happens next?

The API gateway checks an allow list or deny list. It can then talk to an identity provider for authentication and authorization. After that, it applies rate limits and routes the request to the right backend service.

The gateway may transform the request into the appropriate protocol before sending it to a backend microservice. It also handles errors and faults. If a backend takes too long to recover, a circuit breaker can stop sending requests to it for a while.
